# Pushing this project to GitHub

This repo is meant to *be* a portfolio piece, so the goal is a clean, reviewable
repository — code, docs, and a few result media — without the multi-gigabyte raw
dataset or duplicate artefacts.

## 1. What gets pushed (and what doesn't)

**Push these — the project itself**

| Path | Why |
|---|---|
| `app.py` | Streamlit demo (3 tabs: detection, trajectory, scene dashboard) |
| `trajectory_model.py` | BEV planner architecture (reconstructed from the checkpoint) |
| `collision_risk.py` | perception+planning fusion → CLEAR/CAUTION/BRAKE |
| `scene_dashboard.py` | camera+BEV dashboard renderer, GIF builder, timestamp sync |
| `risk_monitor.py` | sequence → annotated risk video |
| `safety_report.py` | sequence → per-scene PDF safety report |
| `run_inference.py` | one-command batch inference |
| `data_preparation_v2.py` | nuScenes → BEV + ego-trajectory data pipeline |
| `vlm_reasoner.py` | local VLM reasoning layer (Ollama backend + mock) |
| `vlm_analyze.py` | 6-camera surround + BEV → VLM → reasoning card |
| `scene_narrator.py` | narrated multi-scene VLM demo (surround+BEV → subtitled clips) |
| `train_trajectory_v3.py` | BEV planner training (augmentation + diversity loss) |
| `requirements.txt`, `yolo_dataset.yaml`, `yolo_dataset/data.yaml` | configs |
| `README.md`, `LICENSE`, `docs/`, `assets/`, `demo/` | docs + portfolio media |
| `.gitignore`, `.gitattributes` | repo hygiene + LFS rules |

**Do NOT push — excluded by `.gitignore`**

| Path | Why | Size |
|---|---|---|
| `venv/` | virtual environment | ~1.6 GB |
| `LIDAR_TOP/`, `yolo_dataset/images/`, `yolo_dataset/labels/` | raw nuScenes data | ~5 GB |
| `checkpoints/` | exact duplicate of `checkpoint_v3/` | 140 MB |
| `runs/detect/`, `train_batch*/val_batch*` images, `visualizations/` | regenerable output | ~40 MB |
| `inference_outputs/` | runtime output (regenerated by the scripts) | — |
| `*.ipynb` | notebooks with embedded outputs bloat the repo | up to 18 MB |
| superseded scripts: `train_trajectory_v2.py`, `enhanced_viz.py`, `visualize_real_trajectory.py`, `visualize_trajectory (1).py` | replaced by the modules above | — |

> The superseded scripts are not git-ignored by pattern (they're real `.py` files);
> just don't `git add` them. If you prefer, delete them before the first commit.



### Demo media for the portfolio
- Put your **YouTube link** in the README (replace `REPLACE_WITH_VIDEO_ID`).
- Drop app **screenshots** in `demo/screenshots/` (names referenced by the README table).
- `demo/scenes/` holds the narrated scene clips (regenerate with real cameras + a vision model before pushing for a coherent demo).
- GitHub doesn't inline-embed a committed `.mp4`; host the video on YouTube (or attach to a Release) and link it — which the README already does.

## 2. Model weights — use Git LFS

GitHub rejects files larger than 100 MB on a normal push, and the BEV checkpoint
(`checkpoint_v3/best_trajectory_model.pth`) is ~140 MB. `.gitattributes` already
routes `*.pt`/`*.pth` through **Git LFS**:

```bash
git lfs install
git lfs track "*.pt" "*.pth"   # already in .gitattributes
```

Files tracked: `checkpoint_v3/best_trajectory_model.pth` (BEV planner) and
`runs/train/nuscenes_yolo/weights/best.pt` (fine-tuned YOLO).

**No Git LFS?** Two alternatives:
- Attach the weights to a **GitHub Release** and add a download line to the README.
- Keep weights out of git entirely (uncomment `*.pt`/`*.pth` in `.gitignore`) and
  host them on Google Drive / Hugging Face, linked from the README.

## 3. Data — not committed

The full nuScenes set is ~200 GB / the bundled samples here are ~5 GB — too large for
git. Document the source instead (the README does): users download
[nuScenes](https://www.nuscenes.org/nuscenes) (the free **mini** split is enough to
run everything) and point the scripts at it. The committed `assets/` GIFs and images
let the README showcase results with no data required.

## 4. First push

```bash
cd <this-folder>
git init
git lfs install

# stage everything except .gitignore'd paths
git add .

# (optional) make sure the superseded scripts aren't staged
git reset train_trajectory_v2.py enhanced_viz.py "visualize_real_trajectory.py" "visualize_trajectory (1).py"

git commit -m "Autonomous perception & planning for ADAS (YOLO + BEV, nuScenes)"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

## 5. Pre-push checklist

- [ ] `git status` shows no `venv/`, `LIDAR_TOP/`, `yolo_dataset/images|labels`, or `checkpoints/`
- [ ] `git lfs ls-files` lists the two weight files
- [ ] README renders (GIFs in `assets/` show, links resolve)
- [ ] Your narrated demo video is in `demo/` (or linked from a Release)
- [ ] `Technical_Report.pdf` is present
